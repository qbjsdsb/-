# 万象图鉴 · Tactical Codex

《王者万象棋》非官方资料库、构筑关系与版本工具站。

线上地址：**https://qbjsdsb.github.io/-/**

## V1 产品结构

V1 不再把数据类型平铺成一组数据库菜单，而是按玩家任务组织：

- **首页**：全站搜索、当前版本、快速入口、阵营概览、最近改动
- **资料库**：英雄、棋手、装备、天赋、效果牌、机制、冷知识
- **阵容**：核心英雄、成型期、4×7 站位和装备/天赋样本
- **版本**：当前 Patch、实体变化和数据同步状态
- **工具**：关系检索、阵容求解器，以及后续自由构筑、Diff、截图识别等

桌面端使用轻量侧栏；移动端在 960px 以下切换为底部导航。

## 设计系统

V1 的设计方向是 **Tactical / Editorial / Precise / Calm**：

- 游戏感来自真实英雄、棋手、装备、天赋和站位，而不是装饰性特效
- 依靠排版、间距、分隔和信息顺序建立层级，减少 Card Soup
- 深色优先，完整支持浅色主题
- 普通内容几乎不使用阴影
- 详情页遵循：答案 → 关系 → 解释 → 完整技术数据

完整规范见：

- `docs/WANXIANG_DESIGN_SYSTEM.md`
- `docs/PRODUCT_V1.md`
- `docs/ARCHITECTURE.md`

## 关系层

英雄详情不是只展示字段。站点会利用 64 套阵容中的成员、装备、天赋和站位数据，自动推导：

- 常见装备
- 相关天赋
- 相关阵容

这层关系由已有结构化数据计算，不额外维护一份容易过期的重复表。

## 阵容求解器

V1 求解器使用本站已核验的阵容作为候选空间，并把两个层次分开计算：

- **随机层**：根据 1—5 阶公共牌库库存、棋手等级对应商店概率、刷新预算和同行卡牌压力，运行可复现的 Monte Carlo 搜牌模拟
- **结构层**：从英雄品阶、核心成本、前排/输出/功能覆盖、阵营集中度、机制关键词联动以及装备/天赋样本完整度计算结构代理分
- **目标函数**：可切换“最稳 / 最强 / 吃分 / 上限 / 低成本”，不同目标使用不同权重
- **边界**：模型分不是实战胜率；当前未模拟完整战斗 AI。模型参数独立存放在 `data/solver-model.json`，版本变化时可单独校准

后续 V2 会把候选空间从已有阵容扩展到 85 名英雄的组合搜索，并加入硬约束、站位和装备/天赋联合优化。

## 数据边界

数据分三层：

1. **自动快照**：`data/catalog/`，每天同步公开结构化上游
2. **人工核验修正**：`data/overrides.json`，自动同步永不覆盖
3. **版本信息**：`data/patches.json`

浏览器只读取本仓库的版本化数据；不会在每次访问时直接依赖 GitHub Raw 数据。

游戏图像通过 `data/manifest.json` 的 `assetBase` 配置远程引用，失败时界面保留文字 fallback。

## “最新”是如何判断的

`data/manifest.json` 同时维护两组数量：

- **verifiedCounts**：已经人工核验并进入本站数据层的数量，是 CI 的硬 Gate
- **expectedLiveCounts**：每日从线上参考站探测到的最新数量，用于发现游戏更新后的数据漂移

例如某次游戏更新把装备从 79 增加到 80：

1. 定时任务会探测到 live=80
2. 网站版本页会显示本地 merged=79 / live=80 的待同步状态
3. CI 不会因为“外部刚更新”而阻止记录这个信号
4. 新装备核验并写入 catalog 或 overrides 后，再把 verifiedCounts 提升到 80
5. 漂移状态消失

这样既不会假装旧数据是最新，也不会让外部更新把自动维护任务锁死。

## 自动更新

`.github/workflows/sync-data.yml` 每天运行：

1. 同步上游 JSON 到 `data/catalog/`
2. 探测 live 英雄 / 棋手 / 装备 / 天赋 / 效果牌数量
3. 运行完整数据校验
4. 有变化时自动 commit + push
5. main 更新后由 GitHub Pages 自动重新部署

人工核验内容始终留在 `data/overrides.json`。

## 数据 Gate

`scripts/validate_data.py` 会检查：

- JSON 完整性
- 合并 overrides 后的 verifiedCounts
- 重复 ID / 名称
- 图片路径
- 阵容英雄名称与站位英雄 ID
- 阵容装备 ID 与天赋 ID 是否存在
- live 最新数量与本站数据是否发生漂移

关系引用错误属于硬失败；live 漂移属于告警。
